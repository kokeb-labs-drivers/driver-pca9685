◆ Error

enum class pca9685::Error : uint8_t
strong

Why a call failed. Every call of the driver returns one of these in its Result.

Values 0 to 9 are the shared base set; chip-specific values start at 16. [[nodiscard]] on the type: a function that returns a bare Error cannot have it ignored either (KB-CPP20-037).

Enumerator
Ok 

The call succeeded.

NotInitialized 

EnsureInitialized() has not succeeded yet, or Deinitialize() ran or a reset was found since.

InvalidArgument 

An argument, the address or a Config field is out of range; nothing was sent (a bank call still sends its switch-offs).

Bus 

A port hook returned false: a NACK of a data byte, a bus error, or a failed output-enable pin write.

Timeout 

Not returned by this driver (no wait polls the chip).

DeviceIdMismatch 

At start-up, a register did not read back what was just written: no PCA9685 answers, or another part does (the chip has no ID register).

Crc 

Not returned by this driver (I2C transfers carry no CRC).

Busy 

Not returned by this driver (the chip has no busy state).

DeviceFault 

Not returned by this driver (the chip reports no faults).

Unsupported 

The port has no output-enable GpioSet() hook, which this call needs.

WriteMismatch 

A register read back differently from what was just written: a write the chip acknowledged but did not keep. Channel calls with Verify::ReadBack; SetPwmFrequency() always (PRE_SCALE ignores a write while awake).

NoDevice 

Nothing acknowledged the address byte: no chip at the address, or it is unpowered. Needs a port with the optional GetLastFailure() hook; without it this is Bus.

DeviceReset 

The chip went through a power-on or software reset since the start, confirmed by two reads: MODE1.AI = 0, or MODE2, EXTCLK, SUBADR1 or PRE_SCALE back at its reset value while the driver's copy differs (sections 7.5, 7.6). The driver drove OE high, wrote ALL_LED_OFF_H and is now uninitialised.

InvalidReply 

A read returned bits the chip cannot send: a read-only bit set, or an inconsistent MODE1/MODE2/SUBADR1 frame. A floating, stuck or shared line, never data.

Asleep 

The registers were written, but the chip is (or may be) asleep, so the outputs do not follow until Wake(); for a switch-off, an output may hold its last level (section 7.3.1, note 4). DisableOutputs() acts at once.

StateUnknown 

The call depends on a value a failed write left unknown (a channel, the prescaler); nothing was sent. Read it back, or write it again.

ExternalClockLatched 

MODE1.EXTCLK is set on the chip but Config asks for the internal oscillator: the bit is sticky until a power cycle or a software reset (table 5).

◆ SleepMode

enum class pca9685::SleepMode : uint8_t
strong

What Sleep() does with the outputs (section 7.3.1.1).

Enumerator
OutputsOff 

Every channel off first (ALL_LED_OFF_H), then sleep: the safe low-power state; Wake() leaves every channel off.

HoldOutputs 

Sleep with the channels as they are; Wake() restarts them (RESTART). While asleep an output may hold its last level.

◆ PwmForDuty()

constexpr Result< Pwm > pca9685::PwmForDuty ( uint16_t  duty,
uint16_t  phase = 0U 
)
constexprnoexcept

The channel value for a duty cycle and a phase delay.

The output is asserted from count phase for duty counts, wrapping past 4095 into the next period (section 7.3.3, example 2). Staggering the phase of several channels spreads their switching edges and the supply current surges.

Parameters
duty0 (off) to kFullDuty (on for the whole period).
phase0 to 4095, the delay before the output is asserted.
Returns
The value, or InvalidArgument when either argument is out of range.
