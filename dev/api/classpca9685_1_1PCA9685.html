Detailed Description

template<I2cPort Port>
class pca9685::PCA9685< Port >

Driver for one PCA9685 on a platform port.

Lifecycle: construct with the configuration (no I/O), EnsureInitialized() (every channel off, the configuration written and read back, the oscillator started), use, optionally Deinitialize() (every channel off, asleep). Every call that touches the chip returns Error::NotInitialized until EnsureInitialized() has succeeded once; no call starts the chip implicitly. DisableOutputs() (a pin write) and Deinitialize() work in every state, and once started the switch-offs keep working while uninitialised (after a reset was found).

Channels are numbered 0 to 15 (LED0 to LED15). The driver keeps a copy of every channel it wrote (GetChannel()). A switch-on writes all four registers of the channel in one transfer, and the driver keeps MODE2.OCH = 0, so the four reach the output together at the STOP (section 7.3.2, note 2). Nothing is read back unless the call's last argument is Verify::ReadBack.

Switch-offs are one data byte and never refused. A switch-off is 0x10 to LEDn_OFF_H, or to ALL_LED_OFF_H for every channel (figure 24): one byte is stored or not, and full OFF takes precedence (table 7), so even a failed switch-off never makes a channel more active (a 4-byte burst NACKed part-way could: new ON bytes with the old OFF bytes, applied at the STOP). A channel call whose value is off (full_off), a mask or bank call's off entries (sent first, before any burst), SetAllOff() and DisableOutputs() always send their write, whatever the driver doubts; a call that refuses its switch-ons still sends its switch-offs. Ok from a switch-off means the output is off: while the chip may be asleep holding its outputs (after Sleep(SleepMode::HoldOutputs)), the write is sent and the call returns Asleep; DisableOutputs() then switches off at once.

Resets. A power-on reset (supply below V_POR) or a software reset (general call, 06h) loads every register with its reset value: MODE1 = 0x11 (asleep, AI clear), every channel full OFF (sections 7.5, 7.6). The driver always sets MODE1.AI and never clears it, and writes MODE2, EXTCLK and SUBADR1 (detail::kSubAdr1Sentinel, inert while SUB1 = 0) only at start-up; every reset check reads MODE1, MODE2 and SUBADR1 in one 3-byte burst, and AI = 0 or any of the others different from the copy is reset evidence. SUBADR1 is the sentinel no MODE1 write of the driver can mask. The evidence is confirmed by a second read before the driver acts (rule 12d); acting drives OE high, writes ALL_LED_OFF_H, marks the driver uninitialised and returns DeviceReset. The driver reads them before it writes MODE1 from its copy (Sleep(), Wake(), SetPwmFrequency()), in CheckForReset(), EnsureInitialized() once started and EnableOutputs(), and with every Verify::ReadBack. A reset the driver has not seen yet leaves the chip asleep, and asleep no output can switch on (table 5, note 4); the driver wakes the chip only with a MODE1 write that it follows with a read of MODE1, MODE2, SUBADR1 and PRE_SCALE, so a reset can never leave the chip running on a configuration other than the driver's.

Failed writes. A switch-on or burst whose transfer failed with Bus may have reached the chip, in whole or in part (the bytes before a NACK are stored). The channels it covered become unknown (GetUncertainChannels(), GetChannel() returns StateUnknown) until a successful write or a read; EnableOutputs() refuses while any is unknown. A failed PRE_SCALE write makes the prescaler unknown, and SetPulseWidthUs() refuses until ReadPrescale() or a successful SetPwmFrequency(). A failed MODE1 write that may have woken the chip leaves the wake check pending: the next call runs it first, and a switch-on is refused until it passes. NoDevice, an address NACK, proves nothing arrived: nothing becomes unknown.

Optional port hooks, found at compile time:

Hook Used for Without it
bool GpioSet(CtrlPin, GpioSignal) noexcept OE: disabled first and enabled last by EnsureInitialized(); DisableOutputs(), EnableOutputs() OE is wired low; the two calls return Unsupported

void DelayUs(uint32_t us) noexcept is required: the oscillator start-up wait. A hook declared with the wrong signature (for example void GpioSet(...)) is a compile error.

Find out whether the chip reset since the start: one 3-byte read of MODE1, MODE2 and SUBADR1 (about 90 us at 400 kHz), a second one only to confirm reset evidence; also the pending wake check, when there is one (one more read).

Call it where a supply dip is possible, for example once per control period: a reset the driver has not seen leaves the chip asleep with every channel off, and channel calls keep returning Ok because a write cannot tell (the chip acknowledges it).

Returns
Ok, NotInitialized, NoDevice, Bus, InvalidReply (a read-only bit reads 1, or an inconsistent frame) or DeviceReset (confirmed by two reads; OE high, every channel off, the driver uninitialised: call EnsureInitialized()).

◆ Deinitialize()

template<I2cPort Port>
Result< void > pca9685::PCA9685< Port >::Deinitialize ( )
noexcept

Switch every channel off and put the chip to sleep, its low-power safe state, and mark the driver uninitialised.

Always does its work, whatever the driver believes (never started, started, or a reset found). An address that EnsureInitialized() refuses is InvalidArgument with no I/O (0x70 is LED All Call at power-up). Otherwise it drives OE high first (with GpioSet(); it needs no bus), brings the bus up and sends ALL_LED_OFF_H = 0x10, then, only when the switch-off was sent (asleep, an output still on would be held on), a wake first when an output may be held and MODE1.SLEEP. Ok only when all of it was sent. The driver is uninitialised afterwards either way.

Returns
Ok, InvalidArgument, NoDevice or Bus.

◆ EnsureInitialized()

template<I2cPort Port>
Result< void > pca9685::PCA9685< Port >::EnsureInitialized ( )
noexcept

Start the chip on the first call. Once it has succeeded, a later call runs the reset check (one 3-byte read) and returns Ok, or starts again from step 1 when the chip reset.

Checks the configuration and the address (no I/O when either is bad), brings the bus up, then:

  1. Switches everything off, whatever state an earlier run left: OE high (with GpioSet()), ALL_LED_OFF_H = 0x10 (one byte: it works whatever MODE1.AI holds, section 7.3.1.1), MODE2 with OCH = 0 and the configured drive, inversion and OUTNE, and ALL_LED_OFF_H again, now sure to reach the outputs at the STOP (an earlier run may have left OCH = 1). Each of the four is sent even when one before it failed.
  2. Reads MODE1 and the byte after it (DeviceIdMismatch when they cannot come from a PCA9685; ExternalClockLatched when EXTCLK is set and the internal clock is asked for), writes SLEEP and AI (the oscillator stops, so PRE_SCALE can be written), sets EXTCLK by the two-write sequence of table 5 when asked, writes PRE_SCALE and the SUBADR1 sentinel.
  3. Identity, a check no floating or stuck line can pass (the chip has no ID register): MODE1, MODE2, SUBADR1 and PRE_SCALE must read back exactly what was written, and every channel full OFF.
  4. Wakes the oscillator (MODE1.SLEEP = 0), waits kOscillatorStartUs (internal clock only, table 5 note 2), reads MODE1, MODE2, SUBADR1 and PRE_SCALE once more, and enables OE.

0.5 ms of waiting and thirteen transfers. After a failure the driver stays uninitialised and the next call starts again at step 1.

Returns
Ok, InvalidArgument (the configuration or the address; no I/O), NoDevice, Bus, ExternalClockLatched, DeviceIdMismatch, DeviceReset (the chip reset during the start-up) or WriteMismatch (the chip did not wake).

◆ SetPwmFrequency()

template<I2cPort Port>
Result< void > pca9685::PCA9685< Port >::SetPwmFrequency ( uint32_t  frequency_hz)
noexcept

Change the PWM frequency of all channels (PRE_SCALE, section 7.3.5).

PRE_SCALE ignores writes while MODE1.SLEEP is 0 (table 4, note 1), so: the reset check (MODE1 read), MODE1.SLEEP if the chip is awake (the outputs hold for the moment), PRE_SCALE, a read back of PRE_SCALE (unconditional: the chip acknowledges a write it ignores), then, if it was awake, the wake of Wake() with its restart. Channel counts stay as they are, so pulse widths scale with the period: write them again after it.

Parameters
frequency_hz1 to kMaxPwmFrequencyHz; the prescaler must be 3 to 255.
Returns
Ok, NotInitialized, InvalidArgument (nothing sent), NoDevice, Bus, InvalidReply, DeviceReset or WriteMismatch (PRE_SCALE did not take the value).

Stop the oscillator (MODE1.SLEEP = 1): the low-power mode (section 7.3.1).

SleepMode::OutputsOff first switches every channel off (ALL_LED, never refused) and sleeps only if that write succeeded. SleepMode::HoldOutputs keeps the channels for Wake() to restart; while asleep an output may hold the level it had (the data sheet does not say), so a switch-off then returns Asleep. Both read MODE1 first (the reset check) and write MODE1 from the copy.

Parameters

Returns
Ok, NotInitialized, InvalidArgument (mode; nothing sent), NoDevice, Bus, InvalidReply or DeviceReset.

Result< void > pca9685::PCA9685< Port >::Wake ( )
noexcept

Start the oscillator and the channels again (section 7.3.1.1).

Reads MODE1 (the reset check), writes MODE1 with SLEEP = 0, waits kOscillatorStartUs (internal clock), reads MODE1, MODE2 and PRE_SCALE (the wake check), and when RESTART reads 1 writes it back as 1, which restarts the channels that ran before Sleep(): the data sheet's order, SLEEP clear for 500 us before RESTART.

Returns
Ok, NotInitialized, NoDevice, Bus, InvalidReply, DeviceReset or WriteMismatch (SLEEP still reads 1).
